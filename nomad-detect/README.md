# nomad-detect — does this text read as machine-written?

A real detector, running on your GPU. No API key, no draft leaving the box, no monthly bill.

Two independent detectors answer two different questions, and you need both.

| | question | how | cost |
|---|---|---|---|
| **Binoculars** | would a classifier call this AI? | two local LMs, perplexity ÷ cross-perplexity | ~1 s on the 5090 |
| **style linter** | WHICH line gives it away, and what do I change? | regex + distribution stats | microseconds, no model |
| external *(opt-in)* | what will GPTZero/Originality say today? | vendor API, only if a key is set | per document, paid |

The linter also enforces `prompts/JDE_STYLE.md`, so a draft that passes is in-voice, not merely
undetected.

## The method

Binoculars (Hans et al., 2024) is the strongest published zero-shot detector, and it is the same
premise every commercial checker sells: machine text is too predictable. Raw perplexity alone fails,
because a human writing about a narrow technical subject also looks predictable. So it divides:

```
score = perplexity(text | performer) / cross-perplexity(observer ‖ performer)
```

The performer is an instruction-tuned model, the observer is the same model before tuning. The
denominator asks how surprising the text is to one model given what the other expected, which
cancels the topic out and leaves the machine-ness. **Low score = machine. High score = human.**

Default pair is Qwen2.5-1.5B base + instruct, about 6 GB of VRAM in bf16. Point the env at the 3B
or 7B pair for more separation if the card is free.

## Install

```bash
./install.sh              # venv + torch cu128 (Blackwell) + transformers
./install_service.sh      # systemd user service on :8214, starts at boot, models preloaded
```

Manage it like the other sidecars: `systemctl --user status nomad-detect`,
`journalctl --user -u nomad-detect -f`.

## Use it

```bash
# CLI — exit code 0 pass, 1 revise, 2 fail
./.venv/bin/python check.py draft.md
./.venv/bin/python check.py --lint draft.md      # style only, instant, no GPU
cat post.txt | ./.venv/bin/python check.py -
```

```bash
curl -s localhost:8214/detect -H 'content-type: application/json' \
  -d '{"text":"..."}' | jq '.verdict, .binoculars.score, .style.score'
```

| endpoint | what |
|---|---|
| `POST /detect` | full verdict: statistical band, style score, per-line rewrite hints |
| `POST /lint` | style only, no GPU |
| `POST /calibrate` | fit thresholds to your model pair and your writing |
| `GET /thresholds` | current lines, and whether they were calibrated or are defaults |
| `GET /health` | models loaded, pair, device, which external providers are configured |

## Calibrate it, or the number is a guess

The published threshold (0.9015) belongs to the Falcon-7B pair on the paper's corpus. Different
pair, different domain, different line. `/health` reports `calibrated: false` until you fix that.

```bash
mkdir -p samples/human samples/ai
# samples/human/ ← your real posts, emails, docs. Twenty is enough to be useful.
# samples/ai/    ← the same kinds of thing, generated by the models you actually write with.
./.venv/bin/python calibrate.py --human samples/human --ai samples/ai
./.venv/bin/python calibrate.py --report
```

It writes `thresholds.json`, keyed by model pair, with the accuracy line, the low-FPR line (at most
1% of YOUR writing gets called machine), and the separation it measured.

⚠ The shipped fit uses pre-LLM essays (Paul Graham, Joel Spolsky) as the human side, because they
are provably human and predate 2022. They are a stand-in for Josias's voice, not a substitute.
Drop ~20 of his own pieces into `samples/human/` and refit before trusting the low-FPR line.
`samples/human/` is gitignored on purpose.

## Where it plugs into NOMAD

- **v2 writing lanes** (`v2/detector.py`) — comms and ads draft, get checked, and rewrite once
  against their own findings before the human gate. The detector report rides in the proposal
  payload, so the operator approving a message sees what the detector said. Fails open.
- **MCP** (`mcp-local/nomad_detect.py`) — `detect_ai` and `lint_style` inside Claude Code, so an
  agent checks its own prose before handing it over.
- **console** — `POST /api/detect` proxies here, behind the console's auth.
- **git hook** — `check.py` exit codes gate a commit that touches drafts.

## What it actually measures (fit on 12 human + 25 AI samples, 2026-09-10)

| source | n | binoculars | AUC | style | AUC |
|---|---|---|---|---|---|
| human (Graham, Spolsky) | 12 | 1.0141 | — | 95.8 | — |
| llama3.1:8b | 10 | 0.9524 | 0.817 | 74.6 | 0.996 |
| gpt-4o | 10 | 0.9125 | **0.983** | 70.0 | 0.996 |
| Claude Opus | 5 | 1.0423 | **0.367** | 90.6 | 0.833 |

AUC 0.5 means the channel is blind to that source. Read the Opus row carefully: **the statistical
channel cannot see Opus prose at all.** Opus scores *higher* than the human corpus, which is worse
than a coin flip. The style linter is what carries that case (0.833), and it is why the linter is
not a nice-to-have second opinion.

Every verdict on an uncalibrated pair, or one with a `blind_to` entry, ships with that caveat
attached. The service does not pretend to a confidence it did not earn.

## Honest limits

- No detector is proof. These systems produce false positives on non-native and heavily edited
  writing, and a determined rewrite beats all of them. Treat a `pass` as "no longer obviously
  machine-shaped", never as a guarantee about someone else's checker.
- Under ~48 tokens there is nothing to measure and the service says so.
- The external adapters are written to each vendor's published API shape but have never run here,
  because no key exists on this box. Check the first live response before trusting the number.
- Thresholds fitted on your own samples beat the defaults by a wide margin. Do the calibration.

Ports on this box: 8200 voice · 8210 scraper · 8212 stt · **8214 detect**.
Bound to 127.0.0.1 by default. Set `NOMAD_DETECT_HOST=0.0.0.0` only if a container needs to reach it.
